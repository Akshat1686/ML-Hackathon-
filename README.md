# PathSnap

Reconstructs a driven route from noisy GPS observations and a directed road graph. An eight-candidate classifier supplies emissions to an HMM/Viterbi decoder. The decoder can insert short directed connecting paths and split the trajectory at large GPS gaps or infeasible transitions.

On the 10 student-test trips, the tuned histogram gradient boosting classifier achieved 81.73% observation Top-1 accuracy. Viterbi increased it to 91.47%, with 99.91% route continuity. Top-1 uses the 19,134 observations with aligned reference labels.

## Setup and training

Use Python 3.12. In PowerShell, from the repository root:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pathsnap.train --data "Student folder" --trials 12
.venv\Scripts\python.exe -m pathsnap.visualize
.venv\Scripts\python.exe -m pathsnap.report
```

If the supplied workspace already has a populated `.venv`, use its Python directly. On Linux/macOS the equivalent interpreter is `.venv/bin/python`. Training accepts `--cache` and `--out`. The cache stores derived arrays from authorized data and can be regenerated by changing its directory. The experiment entry point only reads `train` and `student_test`.

Each partition has a directory per trip. If the directory is `00000052`, it contains `00000052.track`, `00000052.nodes`, `00000052.arcs`, and `00000052.route`. The raw data is supplied by the event and is kept outside the repository. Keep evaluator data on Laptop 1.

## Rehearse and deploy

On Laptop 1, run the API in a terminal:

```powershell
.venv\Scripts\python.exe -m pathsnap.api --trips "Student folder/student_test" --host 0.0.0.0 --port 8000
ipconfig
```

On Laptop 2, run the UI from the repository:

```powershell
py -3.12 -m http.server 8080 --bind 127.0.0.1 --directory ui
```

Open `http://127.0.0.1:8080` on Laptop 2, enter `http://LAPTOP_1_IPV4:8000`, connect, and select a trip. Both laptops need to be on a network that allows peer connections on TCP 8000. The UI can render the route without internet access. The development Folium map uses Leaflet from a CDN.

When the organizers provide the ten reserved trip directories, start Laptop 1 with:

```powershell
.venv\Scripts\python.exe -m pathsnap.api --trips "path/to/organizer-trip-root" --mode evaluation --host 0.0.0.0 --port 8000
```

The folder layout follows the student-test convention. The API lists detected trip IDs, predicts from `.track`, `.nodes` and `.arcs`, then opens `.route` for scoring. The response includes predictions and aggregate metrics. Keep the API terminal visible for the evaluator. Capture the real receiving-laptop terminal and UI during the two-laptop rehearsal for the submission PDF. The model-loading command expects the supplied local `results/model.joblib` artifact.

Run the local HTTP check with `.venv\Scripts\python.exe scripts\check_demo.py`. It requests every student-test trip, checks the response structure and verifies the unknown-trip error.

## Reproducible evidence

- `results/inventory.csv` records per-trip validation, geography and connectivity.
- `results/model_comparison.csv` and `results/results.json` contain fold metrics, student-test scores, model parameters, timing and selected configuration.
- `results/bayesian_trials.csv` records the search bounds, every TPE trial and the objective values.
- `results/route_comparison.csv` contains per-trip results for nearest-road, classifier-only and HMM routes.
- `results/folium_map.html` shows a permitted student-test trip with road, GPS, reference and predicted layers.

Observation metrics use the documented reference alignment; inspect its coverage alongside accuracy. The report records assistance and distinguishes measured development results from the event's final evaluation.
